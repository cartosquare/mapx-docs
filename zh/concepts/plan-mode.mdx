计划模式是对话输入行上的那个开关，**默认开启**。开着的时候，MapX 在你批准之前不会动你的项目：先问清它需要知道的、只读地把数据研究一遍、写出计划，然后停下。关掉它，AI 就直接动手。

![对话输入行里的「计划模式」开关，旁边是推理档位与发送按钮](/images/concepts/plan-mode-toggle.png)

## 打开之后有什么不同

| | 计划模式 开 | 计划模式 关 |
|---|---|---|
| AI 可以做 | 读你的图层与文件、查算子说明、向你提问、写计划 | 工具允许的一切 |
| AI 不能做 | 下载或导入数据、建图层/图表/报告、跑分析或工作流 | — |
| 你的项目 | 在你批准之前保持不变 | AI 边做边改 |
| 你拿到什么 | 一份计划书 + 一张决策卡 | 直接的结果 |

只读这条不是写在提示词里的自觉，而是服务端的硬拦：规划轮尝试写入会直接 422 `plan_readonly`。计划需要的数据会在计划里**声明**（来源、定位、体积、许可），批准之后由执行轮去取。

## 流程

<Steps>
  <Step title="说清目标">
    说你想知道什么，而不是用哪个算子 —— 例如"这片风景名胜区里哪些地方生态最敏感、哪些可以适度利用"。
  </Step>

  <Step title="回答提问">
    MapX 会问那些**会改变方案**的问题，通常三个以上，集中在一张卡上：研究区与口径、方法与精度、是否允许大体积下载、交付物形态。每题的第一个选项是**推荐**项，卡上有作答窗口。窗口内没作答，计划会按这些推荐默认继续，并把它们列为假设。
  </Step>

  <Step title="AI 调研">
    它盘点项目里已有的数据，核对坐标系、字段、范围与规模，按要用到的分析模板校验参数，并把结论记成可核对的条目。这一步**什么都不落在你的项目里**：没有图层、图表、报告，也不跑分析。调研期的临时产物只待在 `.plan-research/`，且不允许被导入。
  </Step>

  <Step title="读计划">
    计划是一份文档，不是对话里的一段话：七章，覆盖研究目标、数据与输入、方法与流程、质量核验、风险与局限、交付成果、执行与验收。它带版本号，每一章都标出内容来源。
  </Step>

  <Step title="拍板">
    聊天里出现决策卡。批准它会开一轮新的执行：先取计划里声明的数据，再跑工作流，最后交付图层、表格与报告。
  </Step>
</Steps>

## 决策卡

聊天里这张决策卡是**唯一**能批准计划的地方。卡上显示计划名、状态、步数、输入槽与预估时长，动作有：

| 动作 | 会发生什么 |
|---|---|
| **运行此计划** | 批准该计划，并开一轮执行 |
| **清空上下文执行** | 批准照旧，但执行在新 thread 里跑 —— 调研对话很长时用它 |
| **提交修改** | 按你的意见就地把同一份计划重新调研，产出新版本，再回到你手上 |
| **放弃此计划** | 归档这条计划。项目里已有的东西不会被删，计划也留着可追溯 |
| **接受未绑定并批准** | 只有必填输入还没有数据来源时才出现；批准即把这条风险记录在案 |
| **查看计划详情** | 打开计划工作台阅读 —— 批准本身永远只在这张卡上 |

拍板之后卡片**留在对话里**变成只读记录，所以"批准过什么、改过什么、放弃过什么"都能回看。

![等待批准的决策卡：运行、清空上下文执行、放弃，或提交修改](/images/concepts/plan-decision-card.png)

## 计划书

计划书在工作台里渲染，也可以整份复制成 Markdown。七章分别是：

| 章节 | 里面有什么 |
|---|---|
| 研究目标与范围 | 业务问题、研究区，以及它依据的澄清问答 |
| 数据与输入 | 输入槽与绑定、待取数声明、数据核验 |
| 方法与流程 | 为什么这么选，以及步骤表：步骤、算子、输入、产物 |
| 质量核验 | 静态核验、试算证据、健全性断言 |
| 风险与局限 | 需要你拍板的缺口、按默认走的假设、已知局限 |
| 交付成果 | 这次运行会产出哪些图层、表格、图表与报告 |
| 执行与验收 | 批准后会发生什么，以及结果怎么判定 |

每一章都标了**系统证据**、**AI 判断**或**证据 + 判断**，你能分清哪些来自数据、哪些是 AI 的推断。

## 计划状态

一条计划会经历四种状态：

| 状态 | 含义 |
|---|---|
| **计划中** | 正在调研与起草，还没有可决策的东西 |
| **待审核** | 过了就绪门槛，等你批准 |
| **已批准** | 你批准了某个具体版本，执行的就是那份快照 |
| **已归档** | 被放弃或被取代；留档可追溯，不再可执行 |

改动一条**已批准**的计划会让它回到**待审核**并清空批准，所以改过的计划绝不会沿用旧批准跑起来。

## 什么时候会被拦住

门槛是刻意设的：跑不起来的计划不会被显示成"已就绪"。最常遇到的几种：

| 你看到什么 | 什么意思 | 怎么办 |
|---|---|---|
| 调研尚未完成 | 用户亲口确认的关键问题少于三条 | 继续回答，或让默认口径生效 |
| 必填输入没有数据来源 | 某个槽既没绑定图层、也没声明取数 | 绑定现成图层、写清数据从哪来，或显式接受风险 |
| 取数声明不完整 | 声明的下载缺定位、许可或体积 | 补齐声明，或显式接受风险 |
| 编译不通过 | 某一步引用了不存在的模板或参数 | 提交修改，把那一步改对 |
| `plan_readonly` | 规划轮试图写入你的项目 | 不用处理 —— 这是设计上的拒绝；数据应该写进计划声明 |

## 什么时候关掉它

计划模式是**会话级**设置，跟项目一起保存。批准执行之后，该会话会自动落回关闭状态，后续追问直接动手；需要再规划时手动点亮即可。

**建议开着**：你会照着结果去做事的分析 —— 涉及阈值、预算，或者有别人要读的交付物。
**可以关掉**：快速、可逆的小事 —— 调个样式、查一个数、随手试试效果。
