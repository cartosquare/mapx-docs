15-minute Life Circle Coverage measures the daily-life side of planning: **who can reach a school, a clinic and a park on foot**, and which neighbourhoods carry the largest shortfall. It is the MapX version of a 15-minute life-circle audit, and it deliberately reports two rulers — coverage and accessibility — instead of a single score.

![The Jakarta life-circle run as delivered: three neighbourhood shortfall ramps, ADM4 boundaries and the pinned three-class comparison heatmap](/images/scenarios/15min-life-circle-coverage.jpg)

## What the scenario ships

Seven prepared layers cover Jakarta; the scenario's default study window is Kota Jakarta Pusat (central Jakarta).

| Layer | Data | Role in the study |
|---|---|---|
| Education facilities | OSM education POIs (7,470 city-wide) | Schools that supply the education circle |
| Health facilities | Healthsites.io (2,447 city-wide) | Clinics and hospitals that supply the health circle |
| Road network | Overture transportation | The walking network used for service areas |
| Administrative boundaries | 46 kecamatan (ADM3) | District framing and attribution |
| Green space and parks | OSM green polygons (3,942) | Source of the destination-park set |
| Neighbourhood boundaries | kelurahan (ADM4); 44 in the study area, 1.09 km² average | The evaluation unit that is ranked and named |
| Population | WorldPop, 100 m | Residents at risk of being outside a circle |

All layers come from the [built-in datasets](/en/concepts/builtin-datasets) catalog with styles and attribution attached.

## How the study works

| Stage | Question | What MapX runs | Output |
|---|---|---|---|
| 1. Coverage audit | How much of each neighbourhood is outside the walk? | Select features, Overlay clip/dissolve/erase, Network service area at 800 m, Zonal statistics, Field calculator | Shortfall layer per class with `gap_sum` and a share-of-residents column |
| 2. Service mix and balance | Which neighbourhoods lack one, two or all three classes? | Zonal summary chaining, Overlay dissolve/erase | Neighbourhood summary table with population, coverage count 0–3 and three shortfall columns |
| 3. Accessibility diagnosis | Where is access hardest, even inside the circle? | 2SFCA accessibility, Top N ranking, Label anchors, Charts | Top-10 shortfall boards, per-class accessibility scores and a pinned heatmap |

**One radius makes the classes comparable.** All three classes use an 800 m network walk, the upper end of the 15-minute life-circle standard (GB 50180-2018, 800–1000 m). A class-standard sensitivity — schools 800 m, clinics 1000 m, parks 500 m — is available as a documented variant.

**The park definition is a decision, not a detail.** The shipped green layer contains road verges, golf fairways and tiny slivers. The scenario keeps `leisure = park` polygons of at least 0.5 ha and uses one centroid per park (with the default definition and the shipped data, 33 destination parks in the study area). Relaxing that definition changes the answer dramatically, so the definition is printed in the report.

**Coverage and accessibility answer different questions.** The shortfall layer says whether residents can walk there; the 2SFCA score says how much supply there is per resident within reach. When they disagree, that disagreement is the finding.

## Run it

The screenshots below come from this scenario's reference workspace. Each step names the platform surface it uses, so you can follow the same path in your own project.

### 1. Open the scenario

Open **Scenarios** in the top menu, select this card and choose **Open scenario**. The whole bundle imports at once: every layer keeps its default style, legend, source and attribution, and the camera flies to the study area. Use the **Layers** panel to switch layers on and off before you type anything.

![The Jakarta life-circle scenario opened in the workspace: imported facility layers, the map and the chat panel](/images/scenarios/steps/15min-life-circle-coverage/chat.jpg)

### 2. Ask the suggested question and review the plan

The suggested question is: *"Run a 15-minute life-circle diagnosis for central Jakarta (Jakpus): check the walking service areas of schools, clinics and parks, find coverage gaps and imbalanced districts, and name the areas to prioritise; deliver coverage layers, charts and a report."* [Plan mode](/en/concepts/plan-mode) asks the four decisions that change the answer — study unit, walking radius, supply assumption and deliverables — and fixes the rest, including the park definition, in the plan document.

![The plan workbench for the life-circle scenario: the approved plan and the recorded clarifications](/images/scenarios/steps/15min-life-circle-coverage/plan.jpg)

### 3. Approve the plan and run the analysis

The run uses selection, clipping and erasing to shape the study area, network **service areas** at 800 m for all three facility classes, zonal statistics to count the residents left outside, field calculations for the shortfall shares, the accessibility model (2SFCA) and a chained summary table. The graph shows every branch, including the three facility classes side by side.

![The analysis graph for this scenario: each node is a deterministic operator, with inputs, parameters and artifacts available on click](/images/scenarios/steps/15min-life-circle-coverage/workflow.jpg)

### 4. Style the result on the map

The three shortfall ramps share one break scale, so a dark purple and a dark teal mean the same share; the ADM4 boundary sits on top with neighbourhood labels, and blank space means inside the circle.

![The layer style editor open on a scenario deliverable: renderer, colours, outline, label field and legend controls](/images/scenarios/steps/15min-life-circle-coverage/style.jpg)

### 5. Turn the result into charts and a report

The run produces per-class ranking boards, a three-class comparison and a heatmap that can be pinned to the map while you pan the ramps. The **[report](/en/concepts/reports)** then names the priority neighbourhoods and states the radius, the park definition and the caveats.

![A chart from this scenario opened in the chart editor, with its type, colours and data settings](/images/scenarios/steps/15min-life-circle-coverage/chart.jpg)

![The scenario report opened in the report canvas, with an executive summary, figures and embedded maps](/images/scenarios/steps/15min-life-circle-coverage/report.jpg)

## Example output

<Note>The screenshots above come from one example run with the default settings on the shipped data. They show the shape of the deliverables, not what your run will return.</Note>

A finished run hands back a named, reusable set of deliverables instead of a single map:

- **Layers** — one neighbourhood shortfall layer per facility class, the accessibility scores, the top-10 boards, the neighbourhood summary table as a layer, and the labelled boundary.
- **Tables** — the neighbourhood summary with population, coverage count and the three shortfall columns, plus the per-class ranking boards.
- **Charts** — three class rankings, a grouped comparison and a heatmap, all editable and pinnable.
- **Report** — the diagnosis document naming the priority neighbourhoods, with the radius, the park definition and the coverage caveats.

The layer names follow the run language, but the deliverable set is stable enough to plan a handover around.

## Read the results with care

- **Coverage is a network distance.** When the mapped street network is incomplete, the gap is overestimated; the report says so.
- **A park is represented by its centroid.** The 800 m distance is measured to the park's centre, an accepted approximation when gate data is unavailable.
- **Blank means inside the circle.** In the shortfall layers, unshaded neighbourhoods are covered — they are not missing data.
- **`cov_count` counts intersection, not full coverage.** A neighbourhood that a circle only clips counts as covered; quote the covered area when a borderline case matters.
- **Capacity is not modelled.** The 2SFCA score uses a default capacity of 1, so it ranks within a class only; cross-class comparison uses the shortfall population.
- **The answer is neighbourhood-level.** "Where inside one kelurahan should we build?" is the [Public Facility Siting](/en/concepts/scenarios/public-facility-siting) scenario.
